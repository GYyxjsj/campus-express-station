## 4. 缺陷清单与修复闭环

本轮共发现 **3 个缺陷**（2 代码 + 1 数据），全部修复并复测闭环；另对 4 项"疑似失败"做了定性，确认为脚本断言/权限设计问题而非产品缺陷。

### 4.1 BUG-01（严重·资金）身份码自取联动取消 OPEN 服务单未退托管款

- **现象**：物主凭身份条码到站自取时，若包裹存在 OPEN（无人接单）服务单，系统取消该单但**未退还托管款**，造成资金悬空（S09 探测：期望余额 +3 元，实际不变）。
- **根因**：`IdentityService.pickup` 仅调用 `proxyOrderMapper.markCancelled` 置状态，未走退款逻辑。
- **修复**：`ProxyOrderService` 新增 `cancelOpenForOwnerPickup`（条件更新仅命中 OPEN，防并发重复退款），复用统一退款路径：全额退托管款（含小费）+ 撤销关联授权 + 去向留痕 + 通知；`IdentityService.pickup` 改为调用该方法。
- **复测**：S07/S08/S09 通过（自取放行、OPEN 单联动 CANCELLED、全额退款 +3 元）；G/H 资金闭环不受影响。
- **存量补偿**：对修复前已产生的悬空订单 778，经管理员调账 API 补退 3 元（流水 id 6475，备注标明 BUG-01 补偿），账户余额复原。

### 4.2 BUG-02（一般·健壮性）畸形 JSON 请求体被兜底成 90000 系统异常

- **现象**：请求体 JSON 格式错误/编码非法时，`HttpMessageNotReadableException` 落入兜底处理器，返回 HTTP 500/90000"系统繁忙"，掩盖客户端错误并污染系统异常告警。
- **修复**：`GlobalExceptionHandler` 新增 `HttpMessageNotReadableException` 专用处理，返回 HTTP 400/40001"请求体格式错误"。
- **复测**：E31 断言 HTTP 400 且 code=40001 通过。

### 4.3 BUG-03（一般·数据）扩容遗留 63 条 CLAIMED 死状态保单

- **现象**：代码保单状态机仅 ACTIVE→CLAIM_PAID（到期理赔）/EXPIRED（期内取件或到期失效），不存在 `CLAIMED` 状态；扩容/种子数据遗留 63 条 `CLAIMED`，定时任务 `settleExpired` 只查 ACTIVE，导致其永久滞留且**无理赔入账流水**（全库 INSURANCE 正向流水为 0）。
- **修复（数据层事务）**：
  - 12 条未到期 → 回退 ACTIVE（claimed_at 置空），交由每 10 分钟定时任务正常结算；
  - 51 条已到期 → 按代码 `settleExpired`/`income` 路径补发理赔：钱包余额与 total_earned 增加保额、写入 EARN/SYSTEM 流水（ref_type=INSURANCE）、发送 IN_APP 理赔通知、状态置 CLAIM_PAID 并补 settled_at；
  - 事务提交后 `CLAIMED` 清零，保单状态分布 ACTIVE=81 / CLAIM_PAID=96 / EXPIRED=724，INSURANCE 正向流水 51 笔，资金与状态一致。
- **复测**：S01 探测学生保单无 CLAIMED 死状态通过；全库 `CLAIMED` 计数=0。

### 4.4 疑似失败定性（非产品缺陷）

| 项 | 初判 | 定性结论 |
|---|---|---|
| M05 我的卡券含新券 | 断言"券码=兑换码"失败 | 产品设计：兑换后发放的券码为新生成码，不等于兑换码。修正断言为"REDEEM 来源+UNUSED+券名"后通过 |
| Q19 新增广告 | position 字段 40001 | 脚本字段错误：广告接口实际字段为 slotKey/theme/weight/content。修正后通过 |
| S02 托管中退回 | 学生调退回 40300 | 权限设计：包裹退回登记为员工操作（parcel:inbound）。改用 staff 触发服务单守卫，83004 拦截通过 |

## 6. 遗留事项与建议

1. **AI 应答时延**：E27 真实大模型调用约 6.9s，属外部接口网络耗时；建议生产配置超时与降级文案，避免阻塞感（当前未配置 Key 时已优雅降级）。
2. **CLAIMED 历史数据**：已按代码路径补发理赔并清零；建议后续种子/扩容脚本严格使用代码状态机枚举（ACTIVE/CLAIM_PAID/EXPIRED），避免再引入死状态。
3. **公告「不再弹出」**：按产品设计由前端本地勾选记录（localStorage），服务端 notice_read 仅留痕、不过滤 popup；已据此修正回归断言（P19），非缺陷。
4. **深翻页性能**：当前 offset 分页在万级数据下仍 < 10ms；若数据量再增一个数量级，建议对台账类列表引入游标/键集分页。
