# 校园快递驿站取件提醒与代取授权管理系统 —— 总体设计文档

> 版本：v1.0　|　日期：2026-11-16　|　技术栈：Spring Boot 2.7 (WAR) + Spring MVC + MyBatis + PostgreSQL + Vue3 + Element Plus + 外置 Tomcat 9

## 1. 项目概述

### 1.1 背景与目标

高校快递末端普遍存在三类痛点：

1. **取件不及时**：学生上课/外出导致包裹滞留，驿站货架周转率低，缺少自动化、可追踪的取件提醒机制；
2. **代取无授权、无审计**：同学间口头代取易引发错领、冒领纠纷，缺少"授权—凭证—核销—留痕"的闭环；
3. **管理粗放**：入库靠手工登记，取件码明文可猜，滞留件无预警，运营数据无看板。

本系统面向校园驿站场景，提供 **包裹全生命周期管理、多渠道取件提醒、代取授权闭环、RBAC 权限与审计、运营数据看板** 五大能力，按企业级工程规范实现（统一响应/异常/日志/参数校验/事务边界/状态机约束），并支持以 **WAR 包部署到外置 Tomcat** 的传统企业交付形态。

### 3.3 核心业务流程

**流程 A：入库 → 提醒 → 本人取件**

```
驿站员扫码/录入运单号+收件手机号
  → 匹配学生(手机号) → 生成取件码(6位数字, SecureRandom) + 分配货架位
  → parcel 状态 IN_STOCK，写 pickup_code、shelf_id、inbound_time
  → NotificationService 生成提醒(IN_APP + SMS模拟 + EMAIL模拟)
  → [定时] 24h 未取 → 催领提醒；72h 未取 → OVERDUE + 管理员告警
学生到站报取件码 → 驿站员核销
  → UPDATE parcel SET status='PICKED_UP' WHERE id=? AND status IN ('IN_STOCK','OVERDUE')
     AND pickup_code=?   （影响行数=0 → 报"取件码错误或已出库"，天然防并发重复核销）
  → 写 pickup_record(本人) + 操作日志
```

**流程 B：代取授权 → 代取核销**

```
学生A(授权人) 选择包裹P + 学生B(被授权人) + 有效期
  → 校验：P 属于 A 且在库；P 无 ACTIVE 授权；B 存在且 ≠ A
  → proxy_auth(ACTIVE, auth_code=8位, expire_at=now+≤72h, parcel_id=P)
  → 给 B 发站内提醒"你有一条代取委托"
学生B 到站出示 auth_code（A 可另行告知取件码，或 B 凭授权码由驿站员核对）
驿站员录入 auth_code + pickup_code
  → 校验授权 ACTIVE 且未过期且 parcel 匹配且取件码正确
  → 事务内：parcel→PICKED_UP(proxy) ; proxy_auth→USED(used_at) ;
     pickup_record(pickup_type=PROXY, owner=A, picker=B, auth_id)
  → 给 A 发"包裹已被代取"提醒 + 操作日志
```

### 3.4 包裹状态机

```
IN_STOCK(在库) ──本人/代取核销──▶ PICKED_UP(已取件)
    │ 超滞留阈值(定时)
    ▼
 OVERDUE(滞留) ──核销──▶ PICKED_UP
    │ 驿站员登记退回
    ▼
 RETURNED(已退回)
```

约束：所有状态迁移通过 **带前置状态条件的 UPDATE** 完成（乐观并发控制），影响行数为 0 即拒绝，避免"重复出库/重复核销"。授权状态机：`ACTIVE → USED / REVOKED / EXPIRED`（终态不可逆）。## 4. 数据库设计（PostgreSQL）

```

### 4.2 表清单（12 张）

| 表 | 说明 | 关键约束 |
|---|---|---|
| sys_user | 用户（学号/工号、姓名、手机号、BCrypt 密码、状态） | username UNIQUE；phone 索引 |
| sys_role | 角色 | role_code UNIQUE |

> 完整 DDL 见 `sql/01_schema.sql`，种子数据见 `sql/02_seed.sql`。

### 4.3 关键 PostgreSQL 特性使用

- `BIGSERIAL` 主键、`TIMESTAMPTZ` 时间戳（统一 UTC 存储，JDBC `serverTimezone` 处理）；
- **部分唯一索引**保证业务约束：
  `CREATE UNIQUE INDEX uk_proxy_active ON proxy_auth(parcel_id) WHERE status='ACTIVE';`
- JSONB 扩展字段 `parcel.extra`（重量、备注、异常照片 URL 等），避免频繁加列；
- 统计查询使用 `date_trunc('day', ...)` 聚合近 7 日趋势。

### 6.1 安全

1. **密码**：BCrypt（cost=10）存储，绝不明文/MD5；登录失败统一提示，不区分"用户不存在/密码错"。
2. **取件码**：`SecureRandom` 6 位数字，仅驿站员入库时生成并展示给物主（站内提醒携带）；核销即随包裹终态失效；核销接口按驿站员权限开放，学生端不回显他人取件码。
3. **授权码**：8 位大写字母数字（剔除 0/O/1/I），`SecureRandom` 生成，DB 唯一约束 + 重试；绑定单包裹、限时（≤72h）、可撤销、一次性（USED 终态）。
4. **JWT**：HS256，密钥从配置/环境变量注入（生产必须改默认值）；2h 过期；拦截器统一解析，`UserContext` ThreadLocal 传递，请求结束清理。
5. **越权防护**：学生查询包裹/提醒/授权一律追加 `owner/user_id = 当前用户` 条件；撤销授权校验 grantor 本人。
6. **审计**：AOP `@OpLog(module, action)` 记录操作人、模块、动作、目标 id、IP、结果到 operation_log。
7. **输入校验**：DTO `javax.validation` 注解 + `@Validated`，全局异常处理器转 40001；MyBatis 全部 `#{}` 预编译防注入。

### 6.2 并发与一致性

- 核销/撤销/退回全部使用 **条件 UPDATE（前置状态 + 凭证匹配）**，以影响行数判定成败，无需分布式锁即可防重复核销（单库场景）；
- 代取核销在 **一个事务** 内完成 parcel、proxy_auth、pickup_record 三表写入，任一失败整体回滚；
- `proxy_auth` 部分唯一索引兜底"同包裹仅一条 ACTIVE"，并发发起授权时由 DB 约束拒绝后转业务错误 70004。

### 6.3 提醒策略（可配置）

`sys_config`：`remind.first.delay.hours=24`（首次催领阈值）、`remind.overdue.hours=72`（滞留阈值）、`remind.daily.max=3`（每人每日催领上限）、`auth.max.valid.hours=72`。

- 定时任务每 30 分钟扫描；催领按"包裹维度 24h 内不重复"（查最近一条 REMIND 通知时间）；
- 渠道抽象 `NotificationSender`：`InAppSender`（落库）、`SmsSender`/`EmailSender`（日志模拟，接口预留真实网关接入位）；
- 外置 Tomcat 多实例部署时，定时任务需加分布式锁或仅单实例启用（`task.enabled` 开关，部署文档说明）。

### 6.4 可观测与运维

- 统一日志格式（logback），关键业务 INFO、异常 ERROR 带 traceId（MDC）；
- `/api/health` 健康检查（Tomcat/Nginx 探活）；
- HikariCP 池参数外置；慢 SQL 由 PostgreSQL `log_min_duration_statement` 观测；
- 升级路径：Redis 缓存取件码/未读数、RabbitMQ 异步通知、多实例分布式锁（文档给出演进方案，当前实现不依赖）。

## 8. Tomcat 部署方案（摘要，详见 docs/02-Tomcat部署指南.md）

1. **构建**：`mvn -f backend/pom.xml clean package -DskipTests` → `campus-express.war`（`spring-boot-starter-tomcat` scope=provided，`ServletInitializer` 接管启动）；前端 `npm install && npm run build` → dist。
2. **数据库**：PostgreSQL 建库 `campus_express`，执行 `sql/01_schema.sql`、`sql/02_seed.sql`。
3. **Tomcat**：9.0.x + JDK 8/11；WAR 放入 `webapps/`，context path=`/campus-express`；`conf/Catalina/localhost/campus-express.xml` 可配 JNDI 数据源；`setenv.sh` 注入 JWT 密钥、DB 密码、`task.enabled`。
4. **前端**：Nginx 托管 dist，`/api/` 反代到 `http://127.0.0.1:8080/campus-express/api/`；无 Nginx 时可将 dist 放入 Tomcat ROOT 并同域反代（文档含两种方案）。
5. **验收**：健康检查 → 登录（admin/staff/student 种子账号）→ 入库→提醒→授权→代取核销全链路冒烟。
